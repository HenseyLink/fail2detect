# fail2detect

**Версия 0.9.3-beta.** Проект в бета-версии: проверяйте на тестовом сервере, прежде чем ставить на рабочие ноды.

Защита нод и панели [Remnawave](https://github.com/remnawave) от сканеров РКН, активного зондирования и брутфорса.

Проект объединяет две идеи:

- **[fail2ban](https://github.com/fail2ban/fail2ban)**: читать логи, считать неудачные попытки с одного IP и банить его;
- **[remnawave-reverse-proxy от eGames](https://github.com/eGamesAPI/remnawave-reverse-proxy)**: популярный установщик панели, нод и страницы подписки. Его идеи вдохновили установщик fail2detect.

Главная задача fail2detect — защита уже работающих нод и панелей. Кроме того, в нём есть собственный установщик: файлы панели и страницы подписки берутся из официальных репозиториев Remnawave, а порт ноды и транспорт можно выбрать. fail2detect работает и на серверах, поставленных другими установщиками: защищает их ноды и умеет менять у них порт и транспорт.

## Установка

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/HenseyLink/fail2detect/main/install.sh)
```

Скрипт ставит зависимости (`nftables curl jq`), копирует файлы в `/opt/fail2detect` и создаёт команду `fail2detect`. Затем он предлагает запустить мастер настройки.

Первым шагом мастер подключает панель Remnawave. Он спрашивает адрес панели (если панель закрыта секретным ключом входа — ссылку входа целиком, ключ из неё fail2detect возьмёт сам) и API-токен (Панель → Настройки → API токены). Подключение сразу проверяется, а при ошибке мастер говорит, что не так: токен, ключ входа, адрес или фаервол.

Вместо `fail2detect` можно писать короче — `f2d`: например, `f2d doctor` или `f2d geo`. Если запустить без аргументов, откроется интерактивное меню.

Панель, ноду и страницу подписки fail2detect находит сам. Он смотрит на compose-файлы в `/opt/remnawave`, `/opt/remnanode` и `/opt/subscription` (`docker-compose.yml`, `compose.yaml` и другие варианты имени), на имена сервисов и образы, а если каталог другой — на работающие контейнеры `remnawave/*`. Если роль показывается как «не найдено», запустите `f2d detect`: команда покажет, что именно найдено и почему остановлен демон. Каталог можно задать и вручную: `f2d config RW_PANEL_DIR /путь`.

## Что делает

### 1. Фаервол и порты

Правила лежат в отдельной таблице nftables `inet fail2detect`. Она обрабатывает пакеты раньше UFW и Docker и может их только запрещать. Если пакет разрешён в таблице fail2detect, его дальше проверяют правила UFW, поэтому то, что уже настроено в UFW, продолжает работать.

| Защита | Зачем |
|---|---|
| Закрытые порты + журнал попыток | Сканер видит только Xray и SSH. Остальное молчит |
| API ноды (`NODE_PORT`, 2222) доступен только с IP панели | Сканер не найдёт характерный порт ноды Remnawave |
| Блок-листы сканеров ([antiscanner](https://github.com/shadow-netlab/traffic-guard-lists), [CyberOK «Скипа»](https://github.com/tread-lightly/CyberOK_Skipa_ips)) | Известные сети сканеров отсекаются ещё до рукопожатия. Списки обновляются раз в сутки |
| Сети госорганов РФ (`government`, опционально) | Абонентские пулы операторов, CDN и сети крупнее /22 вырезаются автоматически |
| Скрытие от ping | Сервер не попадает в выдачу массовых ICMP-сканов |
| Защита docker-портов | Docker публикует порты в обход UFW. fail2detect это закрывает |
| Анти-флуд (опционально) | Бан за шквал новых соединений прямо в ядре |
| Безопасное применение | Если не подтвердить, что SSH работает, через 60 с правила откатываются |

Режимы работы:
- `ufw` (на сервере уже настроен UFW): списком открытых портов управляет UFW, а fail2detect добавляет поверх баны и защиту;
- `nft` (UFW нет): fail2detect сам закрывает всё, кроме SSH, Xray и явно открытых портов.

### 2. Баны по принципу fail2ban

| Jail | Источник | Что ловит | По умолчанию |
|---|---|---|---|
| `sshd` | journald | перебор паролей, SSH-сканеры | вкл, 5 за 10 мин → 1 ч |
| `portscan` | журнал ядра | перебор закрытых портов и API ноды | вкл, 6 **разных** портов за 10 мин → 6 ч |
| `flood` | журнал ядра | записывает баны анти-флуда | вкл |
| `panel` | `docker logs remnawave-nginx` | запросы к панели без секретного ключа входа (ответ 444) | вкл на сервере с одной панелью |
| `reality` | лог Xray | невалидные Reality-подключения (активное зондирование) | выкл, включается `fail2detect node logs` |

Повторный бан того же IP длится вдвое дольше, максимум 30 дней. Баны переживают перезагрузку. Никогда не банятся частные сети, IP панели, белый список и адрес вашей текущей SSH-сессии.

Jail'ы — это файлы `/etc/fail2detect/jail.d/*.conf`. Синтаксис похож на fail2ban, IP в регулярке обозначается `<HOST>`. Регулярки можно проверить на реальных логах командой `fail2detect jail test sshd`.

### 3. Журнал аудита

В `/var/log/fail2detect/audit.log` (TSV) записываются все баны, разбаны, пропуски из-за белого списка, смена портов и изменения фаервола. Для каждого бана указаны страна и строка лога, которая к нему привела.

```bash
fail2detect log                     # последние 50 записей
fail2detect log --ip 1.2.3.4        # история конкретного IP
fail2detect log --action BAN --today
fail2detect stats                   # топ jail'ов, стран, подсетей
fail2detect unban 1.2.3.4           # разбанить чистый IP
fail2detect unban all               # снять все баны
fail2detect trust add 1.2.3.4       # и больше никогда не банить
```

Уведомления о банах можно получать в Telegram: задайте `TG_BOT_TOKEN` и `TG_CHAT_ID`.

### 4. Установка: любой порт и транспорт

```bash
fail2detect install panel     # панель (+ страница подписки, + нода на этом же сервере)
fail2detect install node      # на сервере ноды: автоматически через API панели или вручную
fail2detect node add          # на сервере панели: профиль + нода + хосты + squad, выдаёт команду для ноды
fail2detect install sub       # страница подписки (на сервере панели или отдельно)
```

| Транспорт | Что это | Что нужно на ноде |
|---|---|---|
| `tcp-reality` | VLESS + TCP + Reality + Vision | домен (selfsteal) или чужой сайт |
| `xhttp-reality` | VLESS + XHTTP + Reality | то же |
| `xhttp-tls` | VLESS + XHTTP + TLS (можно за CDN) | домен + сертификат |
| `grpc-reality` | VLESS + gRPC + Reality | домен (selfsteal) или чужой сайт |
| `grpc-tls` | VLESS + gRPC + TLS | домен + сертификат |
| `hysteria2` | Hysteria 2, QUIC/UDP (+ обфускация Salamander) | домен + сертификат, UDP-порт |

Как это устроено:
- **Порт** любой, Hysteria 2 работает по UDP. Фаервол открывает нужный протокол сам.
- **Selfsteal для Reality.** Сканер, пришедший на порт Reality, и человек, открывший домен ноды в браузере, видят обычный сайт. Его обслуживает свой nginx через `/dev/shm/nginx.sock`, сертификат выпускается автоматически.
  - **Сайт** — небольшой сайт компании: главная, «Услуги», «О компании», «Контакты», оформленная страница 404, `robots.txt`, `sitemap.xml`, favicon. Отрасль (студия, консалтинг, логистика, хостинг), название, город и цвета выбираются случайно, поэтому сайты разных нод не похожи. Несуществующие адреса отдают настоящий 404, как у обычного сайта.
  - **Открывается по ссылке.** Если Reality стоит не на 443, а 443 свободен, nginx слушает 443 сам. HTTP (80) переводит на HTTPS. Сертификаты при этом выпускаются через webroot, без остановки nginx.
  - **Проверка:** `fail2detect web check` смотрит глазами сканера: nginx за сокетом, каждый порт Xray, прямой 443 и HTTP. Проверка запускается и в конце `install node`, и в `doctor`. На ноде, установленной раньше, маскировку чинит `fail2detect web selfsteal <домен ноды>`, переустанавливать ничего не нужно.
  - **Свой сайт:** положите файлы в `/var/www/fail2detect` (`index.html` — главная, `404.html` — ошибка), fail2detect их не тронет. Новый случайный сайт: `fail2detect web site regen`.
  - Вместо своего сайта можно указать чужой (`www.example.com:443`).
- **Сертификаты.** Сначала fail2detect ищет готовый сертификат: от certbot или от Caddy, если сервер ставили с Caddy (тогда порт 80 занят им, и выпускать второй сертификат не нужно). Если готового нет, выпускает через Let's Encrypt: HTTP-01 (порт 80 открывается на минуту) или Cloudflare DNS. Если выбранный способ не сработал, скрипт сразу предложит другой. Сменить способ можно командой `fail2detect cert method`, посмотреть сертификаты — `fail2detect cert list`. Продлённый сертификат (certbot или Caddy) сам копируется в ноду (`/etc/xray-certs`).
- **Панель** скрыта за секретным ключом в ссылке входа: без него nginx рвёт соединение (444). API доступно по Bearer-токену.

**Два режима установки ноды (`install node`):**
- **Автоматически.** Вы указываете адрес панели (или ссылку входа целиком) и API-токен. Дальше fail2detect сам создаёт профиль конфигурации, ноду и хосты, добавляет inbound'ы в squad, берёт SECRET_KEY через API, запускает ноду и ждёт, пока панель её увидит.
- **Вручную.** Вы создаёте ноду в панели сами и вставляете её SECRET_KEY, а fail2detect ставит и настраивает сервер.

**Несколько транспортов на одной ноде.** Можно выбрать несколько транспортов сразу (номера через пробел) или готовый набор: Reality 443/tcp + Hysteria2 443/udp + gRPC 8443 + XHTTP 4443. Если провайдер глушит один транспорт (например, UDP для Hysteria2), клиент переключается на другой. У каждого транспорта свой хост в подписке: «Нода · Reality», «Нода · Hysteria2», «Нода · gRPC», «Нода · XHTTP». Ключи Reality у всех транспортов общие. Порты одного протокола не пересекаются.

Если установка ноды оборвалась, например на выпуске сертификата, `install node` можно запустить снова: он увидит незавершённую установку и предложит начать заново.

**Переустановка и удаление** (например, если установка прошла с ошибкой):

```bash
fail2detect reinstall node    # удалить ноду (с резервной копией) и поставить заново
fail2detect remove node       # удалить ноду с сервера; по желанию — и из панели
fail2detect reinstall panel   # переустановить панель
fail2detect remove panel      # удалить панель
```

- **Резервные копии** создаются всегда и лежат в `/var/lib/fail2detect/backup`: у ноды — архив её каталога, у панели — архив каталогов и дамп базы.
- **Нода.** Закрываются порты Xray (SSH не трогается). Если подтвердить, в панели удаляется сама нода, её хосты и профиль — профиль только если его создал fail2detect (`f2d-…`) и им больше никто не пользуется.
- **Панель.** Docker-том с базой (пользователи, подписки) удаляется только после ввода слова «удалить», иначе он сохраняется. При новой установке fail2detect найдёт старую базу и предложит либо подключить её (пароли возьмёт из архива), либо начать с чистой.

### 5. Смена порта и транспорта у работающей ноды

```bash
fail2detect node transport          # сменить транспорт и/или порт (например tcp-reality:443 → xhttp-reality:8443 или → hysteria2)
fail2detect node add-transport      # добавить к ноде запасные транспорты (старый не трогается)
fail2detect node port 8443          # только перенести порт
fail2detect node api-port 32222     # сменить NODE_PORT (2222) в compose, UFW и панели
fail2detect node inbounds           # посмотреть inbound'ы, порты и транспорты
```

`node transport` делает всё согласованно:
1. Готовит ноду, пока она ещё работает на старом конфиге: сертификат, монтирование в контейнер, selfsteal-сайт, фаервол TCP/UDP.
2. Пересобирает inbound с тем же tag. Ключи Reality и path сохраняются, где это возможно.
3. Перепривязывает ноды, хосты и squad'ы, если панель выдала inbound'у новый uuid.
4. Обновляет хосты: порт, SNI, path и ALPN уходят клиентам в подписку.

Если нода на другом сервере, fail2detect покажет команду `fail2detect node prepare …` для неё и подождёт подтверждения. Только после этого он изменит панель.

**Нода от другого установщика.** Установите на неё fail2detect и выполните `node transport` (или `node prepare` на ноде и `node transport` на панели). fail2detect не трогает уже работающий nginx: Reality продолжает работать через его сокет, а для TLS-транспортов берётся сертификат, уже выпущенный для домена.

**Почему популярные установщики не ставят ноду на 8443.** Они жёстко прописывают 443 в нескольких местах:
- правило UFW `allow 443/tcp`;
- inbound в профиле конфигурации (`port: 443`);
- хост (порт, который уходит клиентам в подписку);
- финальная проверка `curl https://домен` (по умолчанию на 443).

Если ставить на 8443, проверка падает, и установщик сообщает, что нода не подключилась. Есть два выхода: поставить ноду на 443 и затем выполнить `fail2detect node port 8443`, либо сразу ставить через `fail2detect install node`.

**Вручную, без скриптов.** Порядок такой:
1. На ноде: если меняется протокол, откройте новый порт в UFW (`ufw allow 8443/tcp`, для Hysteria — `/udp`).
2. Для TLS-транспортов на ноде: положите сертификат в каталог, смонтированный в контейнер `remnanode`.
3. В панели, Профили конфигурации: поменяйте у inbound'а `port` и `streamSettings`. Готовый JSON выдаст `fail2detect node inbound-json <транспорт> <порт> <домен>`.
4. В панели, Хосты: поменяйте порт, SNI и path.
5. Проверьте, что inbound включён у ноды и в squad'е.

API-токен берётся в таком порядке:
- после `install panel` — токен fail2detect;
- иначе — токен, сохранённый установщиком (`/usr/local/remnawave_reverse/token`);
- если нет ни того, ни другого, fail2detect спросит токен один раз.

Если панель на другом сервере, укажите `RW_API_URL` и, если панель закрыта cookie-ключом, `RW_API_COOKIE`.

После смены порта или транспорта клиентам нужно обновить подписку.

### 5b. Российский трафик через ноду: блок или напрямую

Обычно российские сайты идут мимо VPN по правилам маршрутизации в клиенте. Эти правила держатся на гео-базах с GitHub, а базы могут изменить или удалить. Тогда российский трафик пойдёт через ноду, и российские сервисы увидят её IP. Правило на самой ноде закрывает это со стороны сервера.

При установке ноды (`install node`, `node add`, панель с нодой) fail2detect спрашивает, что делать с российским трафиком:
- **блокировать** — российские сайты ноду не видят вовсе. Рекомендуется для зарубежной ноды, предлагается по умолчанию;
- **напрямую** — явно напрямую, в обход других правил и цепочек профиля;
- **не трогать** — по умолчанию для ноды в России, например моста для белых списков.

Правило собрано из нескольких слоёв, чтобы не зависеть от одной базы:
- российские зоны `.ru .su .рф .рус .москва` и другие — работают без всяких баз;
- крупные российские сервисы на иностранных доменах: `yandex.net`, `yastatic.net`, `vk.com`, `userapi.com`, `mycdn.me` и другие;
- `geosite:category-ru` и `geoip:ru` из баз, вшитых в образ ноды;
- по желанию — **все IP-сети России из реестра RIPE NCC**, не с GitHub. Это около 8,7 тыс. IPv4-сетей после склейки и 2,2 тыс. IPv6. Последний полученный список хранится в кэше на случай, если RIPE недоступен.

Правило ставится сразу после блокировки частных сетей, до остальных правил профиля, поэтому его не обойти.

```bash
fail2detect node ru-traffic status          # что сейчас в профилях панели
fail2detect node ru-traffic block --ripe    # блок + сети RIPE во всех профилях
fail2detect node ru-traffic direct          # напрямую
fail2detect node ru-traffic off             # убрать правило
fail2detect node ru-traffic update          # обновить сети RIPE (раз в месяц-другой)
fail2detect install node --ru block --ru-ripe   # без вопросов при установке
```

Команды `node ru-traffic` выполняются там, где есть доступ к API панели. Панель сама разошлёт новый конфиг на ноды. Клиентам всё равно стоит держать «Россия — напрямую» у себя: правило на ноде только страхует.

### 5a. Балансировщик «Авто» и белые списки

В подписке появляется одна запись «⚡ Авто». Клиент сам пингует все ноды пула каждые 30 секунд и держит трафик на двух лучших, выбирая между ними случайно (`burstObservatory` + `leastLoad`).

```bash
fail2detect balancer setup     # выбрать ноды пула и мосты для белых списков
fail2detect balancer add       # добавить ноды в пул
fail2detect balancer add-wl    # добавить мост для белых списков
fail2detect balancer           # состояние
fail2detect balancer remove    # убрать (ноды и хосты остаются)
```

После `install node` и `node add` fail2detect сам предложит включить новую ноду в балансировщик.

Как это устроено:
- Ноды пула — хосты с тегом `F2D_BAL`. Ноду можно добавить и из панели: поставьте хосту этот тег. Перенастраивать ничего не нужно.
- Мосты для белых списков — хосты с тегом `F2D_WL`, например сервер в разрешённой сети. Пока ноды пула отвечают, трафик через мосты не идёт. Когда оператор включает белые списки, зарубежные ноды перестают отвечать на пинг, и клиент сам уходит на мост. Когда списки снимают, клиент возвращается.
- Всё собрано штатными средствами Remnawave: шаблон подписки XRAY_JSON «fail2detect Auto» (на основе Default, с `remnawave.injectHosts` по тегам) и хост-обёртка.
- Отдельный сервер не нужен. «Авто» — виртуальная запись: адрес и inbound у неё взяты от первой ноды пула, но клиент подключается напрямую к нодам пула.
- Запись «Авто» видят только клиенты с подпиской Xray JSON: Happ, INCY, v2rayNG, Streisand, V2Box. По обычной ссылке подписки они получают base64, поэтому `balancer setup` включает в панели «Отдавать JSON на базовом пути подписки». `balancer remove` возвращает настройку, если её включил fail2detect. У внешних squad'ов эта настройка задаётся отдельно. В остальных форматах запись скрыта.

### 6. Тесты: GeoCheck, IPQuality, Speedtest, CensorCheck, бенчмарк

```bash
fail2detect geo               # GeoCheck: в какой стране IP видят сервисы, CDN и гео-базы
fail2detect geo --full        # то же без маскировки IP (по умолчанию 78.135.*.*)
fail2detect ipquality         # IPQuality: репутация IP этого сервера
fail2detect ipquality 1.2.3.4 # IPQuality по другому IP (разделы 1–4)
fail2detect speed             # живой дашборд: скорость, задержка в простое и под нагрузкой, потери UDP
fail2detect speed --quick     # то же, фазы по 5 с
fail2detect speed --plain     # без дашборда, только итог (для ssh без цвета, логов)
fail2detect speed --json      # итог в JSON
fail2detect speed history     # последние 20 замеров
fail2detect bench             # бенчмарк: скорость и пинг до провайдеров России и зарубежа
fail2detect censor            # CensorCheck: что режет DPI (ТСПУ) на этом сервере
```

**GeoCheck** спрашивает у самих сервисов, в какой стране они видят этот IP, отдельно по IPv4 и IPv6. Каждый сервис пользуется своей базой, поэтому ответы расходятся, и ради этого отчёт и нужен. Проверяются три группы:
- **популярные сервисы** (21): Google, YouTube, Twitch, ChatGPT, Netflix, Spotify, Reddit, Disney+, доступность Gemini, YouTube Premium, капча Google, Apple, Steam, TikTok, Ookla, JetBrains, PlayStation, Microsoft и другие;
- **CDN**: ближайшие узлы Cloudflare, YouTube и Netflix;
- **гео-базы** (17): MaxMind, RIPE, ipinfo, ipregistry, ip2location и другие.

В конце отчёта перечислено, кто видит не ту страну. Способы определения регионов взяты из [ipregion](https://github.com/vernette/ipregion) (MIT), код свой.

**IPQuality** — отчёт о репутации IP. Его структура повторяет [IPQuality](https://github.com/xykt/IPQuality), но код свой. Если у сервера есть IPv6, разделы 1–4 строятся отдельно для IPv4 и IPv6, а сервисы проверяются по обоим протоколам. Источники: IPinfo, ipregistry, ip-api, proxycheck.io, Scamalytics, IP2Location, DB-IP и AbuseIPDB. AbuseIPDB работает только с бесплатным ключом (abuseipdb.com → Account → API), который задаётся командой `fail2detect config ABUSEIPDB_KEY <ключ>`. Без ключа его колонка помечена «нужен ключ». Разделы отчёта:
1. **Основное:** ASN, организация, rDNS, подсеть, координаты, фактический регион и регион регистрации, тип IP (нативный или вещательный).
2. **Тип IP:** провайдер, хостинг, мобильный или VPN — по мнению каждой базы, включая IP2Location и AbuseIPDB.
3. **Оценка риска:** шкалы proxycheck, Scamalytics, IP2Location (Fraud Score) и AbuseIPDB (Confidence of Abuse, число жалоб).
4. **Факторы риска:** таблица «база × прокси / Tor / VPN / сервер / абьюзер / бот».
5. **Сервисы:** доступность TikTok, Netflix, YouTube Premium, Prime Video, Reddit, ChatGPT, Claude, Gemini.
6. **Почта:** исходящий порт 25, подключение к почтовым сервисам, около 20 чёрных списков (DNSBL).

Для ноды VPN самые важные разделы 2–4: по ним сервисы отличают VPN-сервер от обычного абонента.

**CensorCheck** показывает, что режет DPI (ТСПУ) на сервере. Полезнее всего запускать его на российских серверах: мостах, релеях, серверах для белых списков.

```bash
fail2detect censor                       # 22 сайта + 10 зарубежных хостингов, около минуты
fail2detect censor youtube.com x.com     # только свои сайты
fail2detect censor --no-hosting          # без теста хостингов
fail2detect censor --json                # результаты в JSON
```

- **Сайты.** Список и HTTP/HTTPS-проверки взяты из режима `--mode dpi` в [censorcheck](https://github.com/vernette/censorcheck) (MIT), код свой. Для каждого сайта определяется причина недоступности:
  - DNS-подмена: системный ответ сверяется с DoH (Cloudflare, Google);
  - блок по IP: закрыты порты 80 и 443;
  - DPI по SNI: с SNI соединение TLS обрывается, а тот же IP без SNI отвечает;
  - обрыв TLS при любом SNI;
  - ответ 451;
  - стоп-страница провайдера на HTTP.
- **Контроль.** Сначала проверяются ya.ru и vk.com. Если не открываются и они, значит, сломана сама сеть сервера, а не работает DPI.
- **Зарубежные хостинги: обрыв после 16 КБ.** ТСПУ пропускает начало соединения с VPS и обрывает его примерно на 16 КБ, поэтому VPN и прокси подключаются, но сразу рвутся. С каждого хостинга (Hetzner, DigitalOcean, OVH, Linode, Vultr, DataPacket, Cloudflare) качаются первые 128 КБ. Результат: прошло целиком, оборвалось на N КБ, данные не идут или TLS не установился. Так видно, у каких хостингов VPN-ноды из этой сети будут рваться.
- Адреса 198.18.x.x помечаются как fake-IP локального прокси (Clash, sing-box). Такие сайты проверялись через прокси, поэтому их результат ничего не говорит о блокировках в этой сети.

**Бенчмарк сети** меряет скорость и пинг от сервера до провайдеров в России и за рубежом. Для VPN-ноды это показывает, как быстро до неё дотягиваются пользователи из разных регионов.

```bash
fail2detect bench             # Россия + зарубеж
fail2detect bench ru          # только Россия: Москва, Петербург, Поволжье, Урал, Сибирь (13 городов)
fail2detect bench world       # только зарубеж
fail2detect bench --ping      # только пинг до всех серверов, примерно за минуту
fail2detect bench --quick     # по 4 с в каждую сторону вместо 8
fail2detect bench --threads 1 # в один поток (по умолчанию 8)
fail2detect bench --json      # результаты в JSON
```

- **Россия** меряется через `iperf3` до публичных серверов Hostkey, Дом.ру и Билайна. Список серверов взят из [bench.gig.ovh](https://gig.ovh), код свой. Если сервер занят чужим тестом, fail2detect повторяет попытку и пробует соседние порты.
- **Зарубеж** меряется как в [bench.sh](https://github.com/teddysun/across): через Ookla Speedtest CLI по серверам в США, Канаде, Европе и Азии. CLI скачивается с install.speedtest.net только после вашего согласия с условиями Ookla, выбор запоминается. Если отказаться (или передать `--iperf`), зарубеж меряется через `iperf3` до серверов в Амстердаме, Париже, Дюссельдорфе, Франкфурте, Хельсинки и Нью-Йорке.
- **Пинг** — 5 ICMP-пакетов. Если ICMP закрыт, показывается время TCP-подключения, пометка «≈».
- Шкала ▰ логарифмическая, от 1 до 10 000 Мбит/с, поэтому на одной шкале видны и 5, и 5000 Мбит/с. В итоге — медианы по России и по зарубежью, а также ближайший, самый быстрый и самый дальний сервер.

**Cloudflare Speedtest** меряет канал через speed.cloudflare.com. Методика как у [cloudflare-speed-cli](https://github.com/kavehtehrani/cloudflare-speed-cli), код свой, на bash, ставить ничего не нужно. Порядок замера:
1. 2 с задержки в простое.
2. Скачивание и отдача по 10 с, по 6 потоков с keep-alive. Параллельно меряется задержка под нагрузкой.
3. 50 STUN-пакетов на `stun.cloudflare.com:3478`: потери, RTT, джиттер и MOS.

Как считается итог:
- Скорость считается по окнам 250 мс. Первые 20% фазы, но не меньше 1 с, уходят на разгон TCP и в итог не попадают.
- Bufferbloat — насколько медиана задержки под нагрузкой выросла по сравнению с простоем. Оценки: A+ ≤ 5 мс, A ≤ 30, B ≤ 60, C ≤ 200, D ≤ 400, F — больше.
- Стабильность — разброс скорости (коэффициент вариации). Оценки: A ≤ 5%, B ≤ 10, C ≤ 20, D ≤ 35, F — больше.

Замеры сохраняются в `/var/lib/fail2detect/speedtest`, хранятся последние 100. Клавиши дашборда работают и в русской раскладке:
- `A` — автосохранение в историю вкл/выкл. Нажатие на итоговом экране сразу сохраняет или убирает этот замер. Выбор запоминается, разовый запуск без сохранения: `--no-save`.
- `R` — замер заново.
- `H` — история.
- `Q` — выход.

### 7. Аудит безопасности

`fail2detect doctor` проверяет:
- торчат ли наружу внутренние порты панели (3000, 5432, …);
- открыт ли API ноды всему интернету;
- не обходят ли docker-порты фаервол;
- разрешён ли вход по паролю в SSH;
- какой транспорт у inbound'ов.

## Про TLS-in-TLS

Закрытие портов защищает от **активного** обнаружения, когда регулятор сам сканирует сервер и зондирует найденные TLS-сервисы. Это главное, что делает fail2detect.

Детект «двойного рукопожатия» (TLS-in-TLS) — **пассивный** анализ трафика клиента. Фаерволом сервера его не закрыть. Против него работает транспорт: VLESS + Reality поверх TCP с `flow: xtls-rprx-vision`. `fail2detect doctor` предупреждает, если inbound настроен иначе (ws/grpc/xhttp поверх TLS и т. п.).

## Осторожно: CGNAT

Мобильные операторы в РФ выводят тысячи абонентов через один IP. Если забанить такой IP целиком, VPN пропадёт у всех, кто за ним сидит. Поэтому:
- **Бан не закрывает порты Xray** (`BAN_SCOPE=except-xray`, по умолчанию). Забаненный IP теряет доступ к SSH, API ноды и всему остальному, но VPN у абонентов за этим IP продолжает работать. Прежнее поведение, когда закрывается всё, включается командой `fail2detect config BAN_SCOPE all`.
- **`portscan` считает разные порты**, а не число стуков: сканер перебирает порты десятками, а случайный шум от абонентов за CGNAT приходится на одни и те же.
- **Jail'ы, которые смотрят на соединения клиентов** (`reality`, анти-флуд), по умолчанию выключены или с высоким порогом.
- **Блок-лист `government` (сети госорганов РФ) — только с фильтром.** Это не список сканеров, а перечень сетей госорганов и аффилированных организаций из реестра RIPE. В исходном виде он задевал абонентов: в нём есть GPRS-пулы операторов (`USI_GPRS_USERS1`, `UTEL_GPRS_NET`), CDN NGENIX в сетях МТС, Ростелекома и Билайна, Qrator и клиентские сети. fail2detect вырезает блоки с такими подписями и все подсети крупнее /22, а сети самих организаций (прокуратура, казначейство, таможня, МВД) остаются. Фильтр ошибается в безопасную сторону: лучше пропустить госорган, чем отрезать абонентов. Сканеры РКН и «Скипы» закрывают отдельные списки `antiscanner` и `skipa`.
- **Из всех блок-листов отбрасываются сети крупнее /16**, чтобы одна ошибочная строка не отрезала целый регион.
- **Порты Xray открываются сами.** Если панель прислала ноде новый inbound (другой порт, Hysteria на UDP), демон в течение 30 секунд замечает это и открывает порт. Известные порты не закрываются, даже пока Xray перезапускается. Раньше новый порт оставался закрытым, клиентов дропало, а `portscan` их банил.
- **Снять все баны разом:** `f2d unban all`.

## Резервные копии и перенос панели

Если IP или домен панели заблокировали, панель переносится на другой сервер вместе с пользователями, подписками, нодами и ключами. Ноды переустанавливать не нужно.

```bash
fail2detect panel migrate --to root@<новый сервер>   # всё сразу: копия → SSH → восстановление → IP на нодах
```

Порядок переноса:
1. Здесь создаётся копия.
2. На новом сервере ставится fail2detect, туда по SSH передаётся копия и восстанавливается.
3. fail2detect предлагает по SSH обновить IP панели на всех нодах и остановить старую панель, чтобы две панели не управляли одними нодами.
4. Остаётся переключить A-записи доменов панели и подписки на новый IP. Если старые домены тоже заблокированы, при восстановлении можно указать новые (`--panel-domain`, `--sub-domain`).

Отдельные шаги:

```bash
fail2detect backup create                  # копия: база + секреты + подписка + нода + сертификаты
fail2detect backup create --no-certs       # без /etc/letsencrypt
fail2detect backup list
fail2detect backup send <копия> --telegram # сохранить в Telegram (только зашифрованную; > 45 МБ — частями)
fail2detect backup send <копия> --to root@<сервер>   # на другой сервер по SSH
fail2detect backup restore <копия>         # восстановить на этом сервере
fail2detect backup schedule daily --keep 7 --telegram   # автокопии в 04:20, 7 последних, копия в Telegram
fail2detect node panel-ip <новый IP> --replace <старый>  # на ноде: пустить новую панель
```

- **Что в копии.** Дамп всей базы (`pg_dumpall`), `/opt/remnawave` с `.env` (секреты, пароль БД), страница подписки, нода этого сервера, настройки fail2detect, сайт-маскировка и сертификаты. Копия — один файл `panel-<сервер>-<время>.tar`, с паролем — `.tar.enc` (AES-256, PBKDF2). Хранится в `/var/lib/fail2detect/backup`.
- **Почему ноды продолжают работать.** Ключи нод (`SECRET_KEY`) подписаны ключами из базы панели, а база переезжает целиком. Нодам нужно только разрешить подключение с нового IP панели: API ноды открыт лишь для IP панели. Это делает `node panel-ip`.
- **Ссылки подписок не меняются** (UUID в базе те же). Когда DNS переключится, клиенты обновят подписку по тому же адресу.
- **Пароль SSH спрашивается один раз:** все подключения переноса идут через одно (ControlMaster).
- **После восстановления** fail2detect показывает ссылку входа с секретным ключом (своего nginx или nginx/Caddy установщика remnawave-reverse-proxy) и логин с паролем. Логин и пароль при переносе не меняются, они лежат в базе. Если fail2detect их не знает (панель ставил другой установщик), он прямо пишет «прежние».
- **Нода на том же сервере** записана в панели адресом шлюза docker-сети, а доступ к её API открыт правилом UFW для этой сети. На новом сервере шлюз может быть другим, а правило не переезжает. Тогда панель не передаёт ноде конфиг, Reality на 443 не поднимается, и панель не открывается. Восстановление исправляет адрес и правило само; на уже перенесённой панели то же делает `fail2detect panel fix`.
- **`fail2detect panel check`** объясняет, почему панель не открывается. Он проверяет контейнеры, API, кто слушает 443, DNS-запись домена (указывает ли на этот сервер), страницу входа через этот сервер и подключение локальной ноды. `fail2detect panel url` показывает ссылку входа и учётные данные.
- **При восстановлении** фаервол, SSH-порты и баны нового сервера не трогаются, переносятся только настройки панели: токены, Telegram, способ выпуска сертификатов. Если на сервере уже есть база панели, перед заменой нужно ввести «заменить», и снимается её копия.

## Обновления

Меню, пункт 9 «Обновления». При запуске меню fail2detect раз в 6 часов проверяет, вышла ли новая версия, и предлагает обновиться. После обновления меню перезапускается уже новой версией. Отключить проверку: `f2d config UPDATE_CHECK no`.

```bash
f2d update --check           # есть ли новая версия fail2detect
f2d update                   # обновить fail2detect
f2d rw versions              # версии панели, ноды и подписки на этом сервере, последние релизы, версии нод в панели
f2d rw update                # обновить всё Remnawave на этом сервере
f2d rw update panel|node|sub # только один компонент
```

Remnawave обновляется независимо от версии fail2detect:
- Свежие образы скачиваются с Docker Hub по тегу из `docker-compose.yml`. Контейнер перезапускается, только если образ действительно новый.
- Перед обновлением панели снимается дамп базы в `/var/lib/fail2detect/backup`.
- Если образ закреплён на точной версии (например, `remnawave/node:2.1.0`), fail2detect предложит переключить его на последний релиз.
- Ноды на других серверах обновляются на своих серверах: `f2d rw update node`.

`fail2detect uninstall` снимает таблицу nftables, службы и команду. UFW остаётся как был.
